# 0009 — Pi 1.4.0 differences

## Context

Phase 22 decision 10 moves Pi from 1.3.0 to 1.4.0 (released 2026-10-21). Record 0001 lists the 1.3.0 API surface that the project uses. This record lists the 1.4.0 changes that touch a name in 0001.

Source: the npm tarballs of `@earendil-works/pi-coding-agent`, `@earendil-works/pi-ai`, `@earendil-works/pi-agent-core` and `@earendil-works/pi-mcp` version 1.4.0, unpacked and read (not executed). The `.d.ts` files were compared with the installed 1.3.0 copies under `node_modules`. The 1.4.0 `CHANGELOG.md` was read.

## Decision

Pi 1.4.0 is in use. All four packages move together, because `pi-coding-agent@1.4.0` pins `pi-mcp`, `pi-ai` and `pi-agent-core` at exactly 1.4.0. The project code needs no change.

### Changes that touch a name in 0001

| 0001 name | Change in 1.4.0 | Effect on this project |
|---|---|---|
| `before_provider_headers` (1.1) | Handlers no longer see the OpenRouter, NVIDIA NIM and OpenCode attribution headers. Pi now sets them through the pi-ai `ClientIdentity` (`sdk.js` `buildRequestOptions`). A returned `null` for one of these headers still removes it. | None. No extension uses this event. |
| `setActiveTools`, `SessionManager.open` and resume (2, 6) | On resume, Pi activates an extension tool that the branch never added or removed, unless the tool is registered with `defaultActive: false`. The SDK `tools` allowlist still filters it. | None. The host passes a `tools` allowlist. No tool uses `defaultActive`. |
| `PI_TELEMETRY` (env table) | Same name and values. It now controls the pi-ai client identity. | None. |
| `agent-session.d.ts` line numbers | One private field is removed (line 257) and a 5-line comment is added (near line 368). No public member changes. Lines 258–368 move up by 1; lines after 368 move down by 4. | Line citations in 0001 refer to 1.3.0. |
| `model-config.d.ts` | Additive only: `imageInput` and `sendImageOptInHeader` in provider `compat`, and a new export `ModelsJsonSchemas`. Line numbers after 175 move. | None. |
| `docs/extensions.md`, `docs/models.md`, `docs/custom-provider.md`, `docs/environment-variables.md` | Text added. The cited facts stay the same. The sentence on handler order and unsubscribe moved from line 98 to line 197. | Doc line citations in 0001 refer to 1.3.0. |

The other cited `.d.ts` files (`extensions/types.d.ts`, `sdk.d.ts`, `session-manager.d.ts`, `resource-loader.d.ts`, `skills.d.ts`, `event-bus.d.ts`, `mcp-servers.d.ts`, `pi-manifest.d.ts`, `agent-session-runtime.d.ts`, `index.d.ts`, `config.d.ts`, `extensions/mcp/*.d.ts`, `modes/rpc/*.d.ts`) are identical in 1.4.0. `runner.js`, `session-manager.js`, `resource-loader.js` and `skills.js` are identical too.

### Other breaking changes (no name in 0001)

- pi-ai `ProviderRequestOptions.telemetryContext` is now `telemetry` (`TelemetrySpan`).
- pi-ai removes `lazyStream` (`api/lazy`) and `resolveTranscriptTools` (`utils/transcript`).
- `generateSummary` and `generateSummaryWithUsage` ignore `reserveTokens`. The setting `compaction.reserveTokens` now only sets when automatic compaction starts.
- pi-coding-agent removes `core/provider-attribution` (internal).

The project uses none of these names.

## Consequences

- `pnpm install` adds one new transitive package, `marked-cjk-friendly@0.1.2` (released 2026-09-19), through `pi-tui@1.4.0`.
- 0001 stays the reference for names. Its line citations are for 1.3.0, with the shifts above.
- `tests/contract` passes on 1.4.0 without change.
- Pi awaits `message_end` of an assistant message, extension handlers included, before it runs any `tool_call` hook of that message (`pi-agent-core/dist/agent-loop.js:325`, `:338`; `pi-coding-agent/dist/core/agent-session.js:709-752`). The duplicate tool call id block of phase 30 (`maskedArgs` in `apps/server/src/search-tool.ts`) depends on this. Check it again on a Pi bump.

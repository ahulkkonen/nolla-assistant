# 0001 — Pi 1.3.0 API contract

## Context

The assistant hosts Pi in-process through the SDK and adds custom extensions. This record lists the exact Pi 1.3.0 API surface that the project builds on. It is reference material. It contains no recommendations.

Source: the npm package `@earendil-works/pi-coding-agent` version 1.3.0, unpacked and read (not executed). In this record, `pkg/` is the package root (`package/` inside the tarball). Each fact quotes `pkg/<path>:<line range>`.

Types from the sibling packages `@earendil-works/pi-ai` (`ImageContent`, `Model`, `AssistantMessageEvent`, `Usage`) and `@earendil-works/pi-agent-core` (`AgentEvent`, `AgentMessage`, `Agent`) are not in this tarball. Where a fact depends on them, the record quotes the docs and says so.

## Decision

The project codes against the names below, copied from the 1.3.0 type declarations. A bump of Pi is a separate task, gated by `tests/contract` (see 0002).

### 1.2 Handler type

`types.d.ts:1182`:

```ts
export type ExtensionHandler<E, R = undefined> = (event: E, ctx: ExtensionContext) => Promise<R | void> | R | void;
```

`pi.on()` returns `() => void` (unsubscribe). Handlers run in extension load order, then registration order (`pkg/docs/extensions.md:98`). Dispatch uses a snapshot, so an unsubscribe does not affect a dispatch in progress (`docs/extensions.md:98`; `snapshotEventHandlers` in `pkg/dist/core/extensions/runner.js:765-1237`).

```ts
export interface ToolResultEventResult {
    content?: (TextContent | ImageContent)[];
```

To replace both text and structured content, return `{ content: [...], structuredContent: ... }`. If a handler returns `content` without `structuredContent`, the runner deletes `structuredContent` (`pkg/dist/core/extensions/runner.js:910-915`; `types.d.ts:1110-1112`; `docs/extensions.md:149`).

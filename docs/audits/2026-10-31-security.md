## Blocking

- **`apps/server/src/auth/routes.ts:167-171` (with `limiter` at `:56-73`, `password.ts:6-11`, `infra/compose.yaml:36`)**
  - Attack: an unauthenticated client sends many parallel `POST /api/auth/password` requests. All of
    them pass the rate limit, and the scrypt work can OOM-kill `pa-server`.
  - Evidence: the handler calls `passwordLimit.blocked(req.ip)` before `await verifyPassword(...)`.
    It calls `passwordLimit.fail(req.ip)` only after the verify ends, so requests in flight are not
    counted. Each verify allocates about 128 MiB (N=131072, r=8). `limiter.mjs` sent 30 parallel
    wrong passwords from one IP: the result was `{ '401': 30 }` (30 full verifications, 0 × 429) in
    1.5 s, and the process RSS was 802 MB. The container limit is `mem_limit: 1g`, and the e5 model
    is already loaded there. The four scrypt jobs also fill the libuv threadpool, so `fs.promises`
    and `dns.lookup` (the `fetch_url` resolver) stall. The key is `req.ip` only. An IPv6 client can
    rotate through its /64. Behind a CDN, every client shares the CDN's egress IPs, so 5 failures
    lock out the owner. Containers on the `internal` network can reach port 3000 directly and set
    `X-Forwarded-For` (`TRUST_PROXY: "1"`).
  - Smallest fix: call `fail(key)` before `verifyPassword` (count the attempt, not the result). Add
    a global key next to the IP key (for example `fail('global')` with a limit of about 10/min).
    Allow one scrypt verify at a time (a module-level promise chain). As a deploy note, remove
    `AUTH_PASSWORD_HASH` after you register a passkey.

- **`apps/server/src/bridge.ts:1357` → `apps/server/src/topics.ts:231,240`** (invariant 1)
  - Failure: a topic name that the user types goes to the model unmasked on every title job.
  - Evidence: `topic.accept` stores `name: msg.name?.trim() || p.name` as it is. (The client sends
    `name` from the rename box in `TopicsScreen.tsx`.) `titleJobs.run` reads every topic
    `{ id, name, description }` and sends `Aiheet:\n${JSON.stringify(list)}` to `zdr/task-small`
    directly, with no `pseudo.mask`. The transcript in the same message is masked. A name such as
    "<real person> – divorce" therefore leaves the box in clear text, and the Presidio backstop has
    PERSON off. `chat.rename` masks its text (`bridge.ts:1140`); `topic.accept` does not.
  - Smallest fix: in `topics.ts`, send `(await pseudo.mask(chatId, list)).masked` in place of
    `list`. The `/mask` endpoint takes JSON. Fail closed when `pseudo` is unset, as the claims
    extraction does.

## Should-fix

- **`apps/server/src/approval.ts:94`, `apps/server/src/search-tool.ts:320`** (approval gate)
  - Attack: two tool calls in one assistant message share a call id. After the user approves the
    `fetch_url` or `web_search` card, the gated call (`bash`, `write`, `edit`, `manage_event`) runs
    with no card.
  - Evidence: `guardConfirm` does `approved.add(callId)`. `approvalGate` skips the card for any
    non-harness tool when `approved.has(event.toolCallId)`. The set is cleared only at
    `tool_execution_end`. Pi runs every `tool_call` hook of a message before it executes any call
    (`pi-agent-core/dist/agent-loop.js:417-440`). Pi gives a call with no provider id the id `""`
    (`pi-ai/dist/api/openai-completions.js:310`, `id: toolCall.id || ""`). `dupid.mjs` drives the
    real handlers: fetch (approved) → bash with the same id → `undefined` (pass). The cards shown
    were `['fetch_url']` only. The harness `stamps` and `maskedArgs` maps use the same key.
  - Smallest fix: key `approved` by `${toolName}\u0000${toolCallId}`, or store the tool name and
    compare it in `approvalGate`. Also block a message whose tool calls have duplicate or empty ids:
    add one check in the `masked.extension` handler that keeps a per-message set.

- **`packages/pi-ext-subagents/src/child.ts:18-21`, `packages/pi-ext-subagents/src/workspace.ts:59-83`** (path guard TOCTOU)
  - Attack: the sandbox can create symlinks in the work dir, and the guard only checks before the
    use. A write or read can therefore follow a symlink that is swapped in after the check, to
    `/data/automations/*.yaml`, `/data/agents/prompts/*`, `/data/pi/<user>/models.json` (the model
    base URL) or `/proc/self/environ`.
  - Evidence: the runner mounts `/data/work/<user>` read-write (`services/sandbox-broker/src/index.ts:106`).
    An absolute symlink target such as `/data` resolves in `pa-server`, where Pi's file tools run as
    uid 10001 with plain `fs.writeFile` and `mkdir` (`pi-coding-agent/dist/core/tools/write.js:17-18`).
    `realInside` resolves the path once at `tool_call`. In a child, `checkFileTool` runs before
    `ctx.ui.confirm`, so the window is as long as the user's card. A parallel child's approved or
    auto-approved `bash` can swap a folder for a symlink in that window. In the parent, the gate
    runs before `pathGuard` (`registry.ts:562`, `:615`), so its window is short. The window is still
    there, because other cards of the same message are answered, and other chats or automations
    share the work dir.
  - Smallest fix: in the runner, block symlink creation. Add a seccomp profile to `HostConfig.SecurityOpt`
    in `containerConfig` that denies `symlink` and `symlinkat`. Without symlinks, the guard has
    nothing to race. Also move `checkFileTool` after the confirm in `child.ts`, to match the
    parent.

- **`apps/server/src/bridge.ts:1521-1527`, `apps/server/src/http.ts:45-58`, `packages/protocol/src/index.ts:453-454`** (artifact exfiltration)
  - Attack: prompt injection (a fetched page, a Gmail message, a Drive file) makes the model write
    an HTML or React artifact. When the user opens it, the artifact reads the restored real names
    and navigates its own frame to `https://attacker/?d=…`.
  - Evidence: artifacts are extracted from `message.text` after `restore(...)`, so the sandbox gets
    real values. The frame is `sandbox="allow-scripts"` (`apps/web/src/components/Sandbox.tsx:84`)
    with `default-src 'none'`. That blocks fetch, XHR and images, but no CSP directive blocks a
    frame from navigating itself (`location.href = …`, or `<meta http-equiv=refresh>` without
    script). The `fetch_url` "URL not in the user's messages" card is bypassed this way. HTML and
    React need a click on "Avaa paneelissa" (`MessageView.tsx:187-188`). A weaker form of the same
    leak: Markdown links are restored before rendering, so a link the model wrote can carry real
    values in its URL.
  - Smallest fix: build the sandbox document from the masked message text (surrogates), not from
    the restored text, and restore only in the parent's own text rendering. If real values must
    show inside artifacts, record the risk in `phase-19-viz.md` and show a one-line warning on the
    "Avaa paneelissa" card when the chat is tainted.

- **`infra/litestream.yml:5-14`** (backups)
  - Failure: Litestream replicates `app.db` to S3 continuously as plain SQLite pages. That file
    holds real values: claims and evidence quotes (`packages/db/src/schema.ts:281`, `:314`),
    consolidation proposals (`:155`) and restored chat titles. The bucket provider therefore holds
    personal data in clear text. Only the restic snapshots are encrypted.
  - Evidence: the replica block has no encryption setting. `vault.db` is SQLCipher, but `app.db`
    is not. `docs/deploy.md:197` says "Only the restic backup is encrypted" for the token volume.
    No record covers `app.db`.
  - Smallest fix: if Litestream 0.5.17 supports client-side encryption for the replica, turn it on.
    If it does not, stop the Litestream replication of `app.db` and snapshot it hourly with restic,
    as `entrypoint.sh` already does for `vault.db`. Record the decision.

- **`apps/server/src/http.ts:105-109`** (logging)
  - Failure: Fastify's default request log writes every URL with its query string at `info`
    (`LOG_LEVEL` default). The Files routes carry file names in the query string.
  - Evidence: `GET /api/files/tree?path=`, `/api/files/tree/raw?path=`,
    `DELETE /api/files/tree?path=`, `POST /api/files/tree/upload?path=` and the `cursor=d:<name>`
    of `/api/files/tree` and `/tree/trash` (`tree.ts:546,580,625,706,747`). `reqlog.mjs` logged
    `incoming request: /api/files/tree?root=work&path=Synteettinen%20Henkil%C3%B6%20CV.pdf`. File
    names often hold people's names. AGENTS.md says "Never log or print real values". The OAuth
    callback already uses `logLevel: 'warn'` for the same reason.
  - Smallest fix: in `Fastify({...})`, set
    `logger.serializers.req = (r) => ({ method: r.method, url: r.url.split('?')[0] })`.

- **`infra/compose.yaml:241-246`, `services/pseudo-svc/app/main.py:70-183`** (network segmentation)
  - Attack: any container on the shared `internal` network can call `GET /vault/entities` or
    `POST /unmask` on `pseudo-svc` without credentials and dump every real value. These containers
    are `litellm` (third-party image with internet egress), both Presidio images, `backup` and
    `sandbox-broker`.
  - Evidence: no route in `main.py` has a token or `Depends` check. `internal:` has no
    `internal: true`, so `pseudo-svc` and the Presidio images also have internet egress that they
    do not need. (Presidio's `tldextract` can fetch the public suffix list at run time.)
  - Smallest fix: add a network `pseudo: { internal: true }` with only `pa-server` and `pseudo-svc`
    on it, and remove `pseudo-svc` from `internal`. Put `presidio-*` on a second
    `internal: true` network with `litellm`.

## Nice-to-have

- **`apps/server/src/auth/routes.ts:284-292`, `:49`, `:152-153`.** An unauthenticated client sends
  10,000 `POST /api/auth/passkey/login/options` requests in 5 minutes. The challenge map is then
  full, and passkey login answers 503 for everyone. Options requests never call `fail()`. Fix: call
  `passkeyLimit.fail(req.ip)` on every options request, or put the challenge into the signed cookie
  and drop the map.
- **`services/sandbox-broker/src/net.ts:30-42`.** `isPrivate` accepts `::7f00:1` (IPv4-compatible
  `::/96`), `::ffff:0:7f00:1` (`::ffff:0:0/96`) and `64:ff9b:1::a00:1` (`64:ff9b:1::/48`).
  `net-check.mjs` prints `false` for each. The risk is low while Docker networks have no IPv6. Fix:
  add these three subnets.
- **`services/sandbox-broker/src/main.ts:6`, `infra/compose.yaml:87`, `services/sandbox-broker/src/index.ts:137`.**
  The broker API (`:8100`, which controls the Docker socket) and the proxy (`:3128`) listen on
  `0.0.0.0`. This includes `pa-skill-egress` and `pa-skill-proxy-only`, where runner containers
  live, so a runner can reach them (they are token-protected). A `network: internet` skill joins a
  normal bridge with no filter. It can reach the Docker host gateway (Coolify, SSH) and
  `169.254.169.254`. No skill is vendored today, and the registry never passes `skill`. Fix: bind
  the API to the `internal` interface only. Route `internet` skills through the allowlist proxy
  too, or document the gap in `skills/README.md`.
- **`services/sandbox-broker/src/index.ts:106,138-146`.** `bash` writes to `/data/work/<user>` with
  no size limit. The 10 GB quota covers uploads and Pi writes only (`tree.ts:62`). A command such
  as `yes > f` fills the shared `pa-data` volume, and then SQLite writes fail. Fix: run `du` on the
  work dir after each run and refuse the next run past the quota, or put `/work` on a size-limited
  volume.
- **`apps/server/src/auth/session.ts:7,12-19`, `apps/server/src/http.ts:115-128`.** Cross-site
  requests are blocked only by `SameSite=Strict`. A sibling subdomain is same-site, so it can still
  POST multipart to `/api/files/tree/upload` (files into the work dir) or call
  `/api/auth/sessions/revoke-all`. Fix: when `cookieSecure`, name the cookie `__Host-pa_session`.
  Add one `onRequest` hook that rejects any non-GET `/api/` request whose `Origin` (or
  `Sec-Fetch-Site`) is not `config.authOrigin` / `same-origin`. Exempt the CSP report and the
  OAuth callback.
- **`apps/server/src/auth/session.ts:149-157`.** The 30-day expiry rolls forever, so a stolen
  cookie that is used once every two weeks never expires. Fix: refuse a session whose `createdAt`
  is older than about 90 days.
- **`apps/server/src/automations.ts:233`.** `log.warn({ file, error: err.message })` logs
  `YAMLParseError` messages. These messages quote the failing source line, and the line can hold
  the user's automation prompt. Check: `parse('prompt: Muistuta Synteettinen Henkilö: soita\n  bad: [')`
  gives a message that contains that text. Fix: log `err.name` and `linePos` only.
- **Repository metadata (no secret).** The owner's full name is used as test PII in
  `apps/server/src/memory.test.ts:39`, `services/pseudo-svc/tests/test_mask.py:95` and
  `tests/mcp/src/mcp.test.ts:13`, against the AGENTS.md rule "Tests use synthetic names only". 59
  of the 305 commits have the owner's personal address as author and committer (the others use a
  GitHub noreply address). Synthetic test addresses use `@gmail.com`
  (`services/pseudo-svc/tests/test_mask.py:387`, `tests/pii/corpus.jsonl`), and real people may own
  them. Fix: replace the name with a synthetic one. Rewrite the author address with `git filter-repo
  --mailmap` before the first push if you do not want it public. Use `example.invalid` or
  `example.fi` for test addresses.
- **`infra/Dockerfile.server:4`, `infra/Dockerfile.broker:4`, `infra/compose.yaml:91-147`.** The
  Node base image is pinned by tag only, while every other image has a digest. `litellm` and both
  Presidio services have no `user:`, so they run as the image's default user, which I could not
  check offline. The LiteLLM main image runs as root, and a non-root variant exists. Fix: add
  `@sha256:` to `FROM node:…`, and set `user:` or use the non-root images.
- **`pnpm audit --prod`: 19 advisories (4 low, 10 moderate, 5 high), all transitive.** The 5 high
  ones: `undici@8.10.2` bundled by `@earendil-works/pi-coding-agent@1.4.0` (GHSA-xjj6-f33q-929c,
  GHSA-4w7w-5xrc-9h26, GHSA-2m5v-pch6-74hx, GHSA-qrxm-fqhp-jwvm; patched in 8.12.2) and
  `body-parser@2.3.0` through `@modelcontextprotocol/sdk` > express (GHSA-27r3-jxmh-p828; patched
  in 2.4.0). The moderate and low ones are `fast-uri` 3.1.8 / 4.2.2 (fastify and ajv), the
  remaining `undici` items, `minimatch@10.2.6` and `glob@13.0.6` (`@fastify/static`). Exposure is
  low: Pi's undici talks only to LiteLLM and `mcp-workspace` on internal networks, and the express
  server code of the MCP SDK does not run. The broker's own `undici` is already 8.12.2. Fix: add
  `pnpm.overrides` for `undici`, `fast-uri` and `body-parser` once the patched releases are older
  than 7 days, or take them with the next Pi bump.
- **`docs/plan.md:384`.** Plan section 14 requires a threat-model note in `docs/decisions/` that
  covers prompt injection via tool results, memory poisoning, sandbox escape and token storage.
  None exists. Fix: write it, and include the should-fix items above as decisions or accepted
  risks.
- **`apps/server/src/config.ts:62,87-89`, `services/sandbox-broker/src/index.ts:51`.** The config
  checks fail open. With `PSEUDO_URL` unset, the server runs with no masking and sends real values
  to the model (the compose default prevents this). `LITELLM_MASTER_KEY` has no length check, and
  `.env.example:3` has `change-me`. With `HOST_DATA_DIR` unset, the broker binds the host path
  `/data/work/<user>` (Coolify keeps its own data under the host's `/data`). Fix: when
  `NODE_ENV=production`, refuse to start without `PSEUDO_URL`, with a master key shorter than 32
  characters, or (in the broker) without `HOST_DATA_DIR`.
- **`apps/server/src/zip.ts:120-137`.** The full export uses `openssl enc` AES-256-CBC with no
  MAC. Confidentiality holds (PBKDF2, 600,000 iterations), but someone who can change the file at
  rest can make undetected changes. Fix: record it as accepted for `openssl` compatibility, or add
  an HMAC sidecar.
- **`apps/server/src/bridge.ts:1293`, `apps/server/src/fetch-tool.ts:255-257`.** The text of an
  attachment is appended to the user message, so a URL inside an untrusted PDF or DOCX counts as
  "written by the user". `fetch_url` then GETs it with no card. Only exact URLs match, so this is
  a beacon and not a channel for data. Fix: check `msg.text` only, for example by keeping the
  user-typed text in a separate session entry, or accept the risk and record it.

## Checked and sound

- Masked-only sessions: `pi-ext-pseudo` masks `input`, `tool_result` content, blocks, `details` and `structuredContent`, and the `context_with_system` scan fails closed (`index.ts:37-168`).
- Tool arguments: `tool_call` unmasks in place, but Pi validates on a `structuredClone` (`pi-ai/dist/utils/validation.js:284`), so the stored assistant message keeps the masked arguments.
- Block reasons reach the session unmasked, and every reason I traced is fixed text (approval, path guard, fetch, harness, pseudo).
- Memory, title and claims injections into the session are masked (`pi-ext-memory/src/index.ts:178,215`). Recent titles are masked before injection.
- Title job: the transcript comes from the masked session, and the title is restored only after the call. Claims extraction masks its claims list (`claims.ts:399-410`).
- Subagent children: the pseudo CLI fails closed without `PSEUDO_URL`. The env is minimal, the provider and the model prefix are fixed, and children get no harness, fetch, search or memory tools. Their stderr reaches the session only through the masked tool result.
- One egress URL: `models.json` has only the `zdr` and `open` providers, with `baseUrl` = LiteLLM and `apiKey: '$LITELLM_MASTER_KEY'` (an env reference, not the key). `PI_OFFLINE` and telemetry are off for the server and the children. Embeddings run locally. Search, title, claims and STT go to LiteLLM.
- LiteLLM: `zdr_guard.py` allowlists the model, refuses unknown top-level keys, `extra_body`, plugins and non-function tools, and refuses `open/` when its key is empty. The port is not published, and the image is digest-pinned.
- Approval gate: harness tools always ask, even with the toggle, the profile, an automation or a child. Unattended chats deny every gated tool outside `autoApprove`. MCP writes are forced into `always`.
- Approval card arguments go only to the chat's room, and the push payload is the title only.
- `fetch_url`: http/https only, ports 80 and 443, no userinfo, IP literals checked, and DNS-pinned `publicLookup` (no rebinding). Every redirect is checked again (at most 3), the body is capped at 2 MB and must be a text type, and the HTML stripper runs in linear time. WHATWG normalizes decimal and hex IPv4 hosts.
- Path guard: the realpath of every existing part, a dangling symlink refused, `.trash` hidden, and the `read` name variants checked. Only the race above remains.
- File routes: `O_NOFOLLOW`, `O_NONBLOCK`, a `/proc/self/fd` recheck, never `text/html`, `CSP: sandbox` on raw files, `nosniff`, and `Content-Disposition` with RFC 5987.
- Uploads: a mime allowlist plus a magic-byte sniff, the quota, sanitized names, and `wx` creation that never writes through a symlink.
- Password and session: scrypt N=2^17 with `timingSafeEqual`. The session token is 256-bit random, and only its sha256 is stored. The cookie is `HttpOnly` and `SameSite=Strict`, with `Secure` and HSTS on https.
- Passkeys: user verification required, a server-side challenge with a signed cookie, and registration only with a fresh session. Revoke-all rotates the current token and closes the revoked sockets.
- WebSocket: an exact `Origin` allowlist plus cookie auth. `AUTH_INSECURE_LAN` exists only in `compose.local.yaml`, and `loadConfig` refuses http on a non-loopback host without it.
- App CSP: `script-src 'self'` with no inline script, `img-src 'self' data: blob:` (this blocks Markdown-image exfiltration), `frame-ancestors 'none'`, `base-uri 'none'` and `form-action 'self'`.
- Markdown: `react-markdown` without `rehype-raw`, the default URL sanitizer, and search snippets rendered as text nodes. No `dangerouslySetInnerHTML` in the web app.
- Mermaid: `securityLevel: 'strict'`, the `secure` keys locked against `%%{init}%%`, and rendered under the app CSP.
- Vega-Lite: `vega-interpreter` (no `eval`), and specs with `url` or `href` are refused.
- Sandbox page: it accepts one document, and only from the app origin. It runs on an opaque origin with `default-src 'none'`, so fetch, XHR and WebSocket are blocked.
- Broker: constant-time token compare, a zod-validated body, and a fixed container config (uid 10001, read-only root, `CapDrop ALL`, `no-new-privileges`, pids, memory and CPU limits, network `none` by default). Stale containers are swept at start, and every command is an argument to `bash -lc` inside the runner, never a host shell.
- Containers: `pa-server`, `pseudo-svc`, `mcp-workspace` and `backup` run as uid 10001 with `read_only`, `cap_drop: ALL` and `no-new-privileges`. `compose.yaml` publishes no ports, and `compose.local.yaml` binds `127.0.0.1` by default. The Python deps are hash-locked.
- Secrets in tracked files: none. `scan.py` checked all 1,212 files for key, private-key, scrypt-hash, JWT, VAPID and token patterns. The only hits are synthetic: the DVV example hetu, test e-mails and the restore-drill dummies.
- Secrets in history: none in any added line of the 305 commits. `.env` was never committed, and it is ignored by git and Docker. `.env.example` has placeholders only.
- Test data: the screenshots I sampled show synthetic fixture data, and the `tests/memory-eval` fixtures and results are synthetic.
- Push: the endpoint host allowlist (Apple, FCM, WNS, Mozilla) prevents SSRF, and the payload is the title only.
- OAuth callback: rate limited, `state` and PKCE checked by the MCP server, the code kept out of the logs, and the path is not attacker-controllable.
- CSP report route: no auth, but rate limited, and it logs only the directive, the origin and the path.
- Admin editors: they need auth. Ids are checked before any write, the prompt path stays under `prompts/` after realpath, and `profile_edit` cannot change tools, approvals or the model.
- Accepted by design and documented, not counted above: images go to the model unmasked (phase 3), STT audio goes unmasked through `zdr/stt` (ZDR through the account guardrail), the user's Google address appears in the MCP tool schemas (decision 0005), and a `web_search` query reaches Exa unmasked when it names no vault entity.
- Existing tests: `approval`, `fetch-tool`, `csp`, `policy`, `tree` and `files` pass (59 tests).
